### 3.1 Compliance / App Store

#### QA-C1 · Critical ✔ — Landing page asks for a myshopify.com domain
- **Where:** `app/routes/_index/route.tsx:249-283` (`<Form>` with `<input name="shop" placeholder="my-shop-domain.myshopify.com">`), action at `:114-116` calls `login()`; `app/routes/auth.login.tsx:16-22`.
- **Requirement:** shopify.dev *App Store AI self-review requirements* **2.3.1 "Initiate installation from a Shopify-owned surface"** — "Your app must not request the manual entry of a myshopify.com URL or a shop's domain during the installation or configuration flow." Reviewers are told to search for exactly these inputs.
- **Stale doc:** `scripts/qa/APP-STORE-REVIEW.md:40` and `:64` mark B2 withdrawn ("no such rule") — no longer true.
- **Fix:** remove the shop-domain form from `/`; show a CTA linking to the listing (`https://apps.shopify.com/<handle>`, already available as `listingUrl` in the loader at `:107-108`). Keep the `?shop=` → `/app` redirect. Make `auth.login` redirect-only (no domain form). Remove the now-unused `loginErrorMessage`.
- **Verify:** `grep -rn "myshopify.com" app/routes/_index app/routes/auth.login.tsx` shows no input/placeholder; `/` renders with no form; `/?shop=x.myshopify.com` still redirects into the app; routing/ui-web suites green; update APP-STORE-REVIEW.md B2 → fixed.

#### QA-C2 · Major ✔ — Admin → Debug action has no same-origin check
- **Where:** `app/routes/admin.debug._index.tsx:81-103`. Every other `/admin` action calls `sameOrigin(request)` (9 checked).
- **Impact:** this action turns on shopper-text recording for **every store** and deletes all recordings. SameSite=Lax limits exploitability, but it breaks the K-16 rule and makes APP-STORE-REVIEW.md:229 ("every action same-origin gated") false.
- **Fix:** add the same `if (!sameOrigin(request)) return { ok: false … }` guard used in the sibling admin routes, before `requireAdminUser` reads the form.
- **Verify:** cross-origin POST → rejected; same-origin toggle works; add `/admin/debug` to the admin-auth route list in `scripts/qa/routing.test.ts` (~:413) and the cross-origin check in `ui-admin.test.ts`.

#### QA-C3 · Major — Debug recording is not disclosed and has no access log (PCD)
- **Where:** `admin.debug._index.tsx:86-94` (single global switch; UI copy at :130 says "for every store"), `app/routes/proxy.chat.tsx:47-72`, `app/lib/pipeline/turn-capture.server.ts:144-176`. A recorded turn holds shopper text, the full prompt message list including history, and the shopper-context block (first name, location, "ordered before" — `app/lib/pipeline/shopper.server.ts:50-61`).
- **Conflicts:** published privacy policy (`docs/privacy-policy-page.html` :7 "only on their instructions", :19 logs "never store chat message bodies", :83 cross-store access prevented, §14 advance notice of new data categories). The PCD request submitted 2026-09-11 likely does not describe this access.
- **Also:** reads of shopper content are not logged (`admin.debug.$conversationId.tsx:22-47`, `admin.debug._index.tsx:20-35`); any `AdminUser` can read (no role, `prisma/schema.prisma:779`) — PCD level 2 rules 4 & 6.
- **Severity:** Major while off by default; **Critical the moment it is enabled in production.**
- **Fix (owner decisions marked ◆):**
  1. ◆ Replace the global switch with a per-shop allowlist (shop IDs) and an auto-off after N hours.
  2. Log every read (`logWarn("turn_trace_viewed", …, { by, shopId, conversationId })`).
  3. ◆ Restrict Debug to a root/owner admin (or add a role).
  4. ◆ Publish a privacy-policy clause (support/debug access, 7-day retention) and align the PCD answers **before** enabling in production.
- **Verify:** toggling for shop A records only shop A turns; each detail view writes one log row; policy page updated.

#### QA-C4 · Major — Debug recordings can outlive erasure; data-request export is narrower than redact
- **Where:**
  - `turn-capture.server.ts:120-130` saves fire-and-forget after the turn — a turn finishing during/after `cleanupShop` (`app/lib/jobs/handlers.server.ts:493-496`) or customer redact (`:388-390`) writes its row afterwards.
  - `purgeTurnTraces` (`handlers.server.ts:426-440`) only purges by age; unlike `purgeAppLogs` (`:475-482`) it does not drop rows of uninstalled shops.
  - `turn-capture.server.ts:142-143` saves turns with `conversationId: ""` that still contain `shopperText`; customer redact can't reach them.
  - `customers/data_request`: `app/routes/webhooks.compliance.tsx:25-26` keeps only the email; `app/lib/compliance/data-request.server.ts:81` matches `{ shopId, email }`, while redact matches email **or** `shopifyCustomerId`. The export also omits `turn_traces` although redact deletes them.
- **Fix:** (a) don't persist traces with an empty conversationId; (b) in `purgeTurnTraces` also delete rows whose shop has `uninstalledAt != null`; (c) store `customer.id` (and phone) on `DataRequest` and match the same way redact does; (d) include `turn_traces` in the export, or state the exclusion in policy §10.
- **Verify:** extend `scripts/verify-compliance.ts` — trace written after cleanupShop is gone after the nightly purge; email-less logged-in contact is both exported and erased; still zero-row across all tables.

#### QA-C5 · Major — `app_subscriptions/update` webhook calls the Admin API inline

### 3.2 Tenancy / data integrity

#### QA-S1 · Major ✔ — Shopper can plant turns into another store's Debug conversation
- **Where:** `app/lib/pipeline/index.server.ts:164-167` — the rate-limited path yields `conversationId: input.conversationId ?? ""` (client-supplied, unverified). `observeTurn` stores it (`turn-capture.server.ts:113,121-129`) with the attacker's `shopId`. `admin.debug.$conversationId.tsx:26-29` reads `where: { conversationId }` only and takes the heading store from the oldest row (`:30-37`); `admin.debug._index.tsx:43` groups by conversationId only (also merges every store's `"(no conversation)"` bucket).
- **Scenario:** from any storefront, send ≥11 msgs/min with `conversationId` = shop A's id → fake "Shopper said" turns appear under shop A in Debug. Needs a known cuid and recording on; no shop-A data reaches shop B.
- **Fix:** return `conversationId: ""` on the rate-limited path (widget already handles empty); detail route keyed by `shopId + conversationId` (e.g. `/admin/debug/:shopId/:conversationId`); list grouped by `` `${shopId}:${conversationId}` ``.
- **Verify:** new check — rate-limited turn with a foreign conversationId yields `""`; detail query includes shopId; tenancy-race suite green.

#### QA-S2 · Minor — Permission drift between dashboard `sync-all` and Training sync
- **Where:** dashboard `sync-all` gated by `dashboard` permission; the same syncs on Training use `ai_agent` (`app/routes/app.ai-agent.training.tsx:530,540`). Equivalent today (agents only have inbox + contacts, `access.server.ts:43`).
- **Fix:** gate `sync-all` on `ai_agent` too.
